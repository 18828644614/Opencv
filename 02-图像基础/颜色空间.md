# 颜色空间

颜色空间（color space）可以理解为“`用一组数描述颜色的规则`”。同一个像素，在不同颜色空间中会有不同的数值表示；转换颜色空间，就是把这些数值换一种表达方式。

初学时最容易混淆的两件事是：

1. **颜色空间不是颜色本身**。`BGR`、`HSV`、`Lab` 是不同的坐标系，不是三种不同的颜色。
2. **通道顺序和数值范围必须一起记**。例如 OpenCV 的普通彩色图通常是 `BGR`，而不是 `RGB`；OpenCV 的 `HSV` 中色相 `H`（8 位图）通常是 `0~179`，也不是网上常见的 `0~360`。

## 1. 为什么要转换颜色空间

在 `BGR` 中，一个像素写成 `(B, G, R)`。它适合保存和显示照片，但不一定适合直接完成所有任务：

- **判断明暗、做边缘检测**：只需要亮度信息，灰度图更简单。
- **按颜色分割**：希望把“颜色”和“亮暗”分开，`HSV` 通常比 `BGR` 更直观。
- **计算颜色差异**：希望数值距离更接近人眼感受，可以尝试 `Lab`。
- **处理亮度与色度**：视频、肤色分析等任务有时会使用 `YCrCb`。

转换的核心 API 是：

```cpp
cv::cvtColor(src, dst, code);
```

它会根据 `code` 把 `src` 转换到 `dst`，**不会原地修改 `src`**：

```cpp
cv::Mat bgr = cv::imread(R"(D:\learn\Opencv\data\sample.jpg)");
cv::Mat gray;

if (bgr.empty()) {
    std::cerr << "图片读取失败\n";
    return 1;
}

cv::cvtColor(bgr, gray, cv::COLOR_BGR2GRAY);
```

`code` 还规定了输入和输出的通道顺序。例如 `COLOR_BGR2RGB` 与 `COLOR_RGB2BGR` 方向相反，不能混用。

## 2. 常用颜色空间速查

| 颜色空间 | 通道含义 | 常见用途 | 初学者要注意 |
| --- | --- | --- | --- |
| `BGR` | 蓝、绿、红 | 普通读写、显示、绘图 | OpenCV 默认顺序是 B-G-R |
| `RGB` | 红、绿、蓝 | 与部分图像库、深度学习库对接 | OpenCV 读入后通常要显式转换 |
| `Gray` | 亮度 | 阈值、边缘、轮廓、形状 | 只有 1 个通道，不能当 BGR 访问 |
| `HSV` | 色相、饱和度、明度 | 颜色分割、颜色跟踪 | 8 位 OpenCV 中 `H` 是 `0~179` |
| `Lab` | 亮度、绿红轴、蓝黄轴 | 颜色距离、颜色校正 | 8 位和浮点图的范围不同 |
| `YCrCb` | 亮度、红色色度、蓝色色度 | 视频、肤色、亮度/色度分离 | 不要把它当作可直接显示的 BGR |

没有“最好的颜色空间”。应根据问题选择，并在输入、处理、输出之间保持约定一致。

## 3. BGR：OpenCV 的默认彩色格式

### 3.1 BGR 和 RGB 的区别

很多教材按 `R、G、B` 讲解颜色，但 OpenCV 默认把一个彩色像素保存为：

```text
(B, G, R)
```

例如：

```cpp
cv::Vec3b pixel = image.at<cv::Vec3b>(y, x);
int blue  = pixel[0];
int green = pixel[1];
int red   = pixel[2];
```

如果误把它当成 RGB，常见现象是“红色和蓝色互换”。给需要 RGB 输入的库时，先转换：

```cpp
cv::Mat rgb;
cv::cvtColor(bgr, rgb, cv::COLOR_BGR2RGB);
```

反过来，如果外部库返回的是 RGB，而 OpenCV 要显示或保存，通常转换回 BGR：

```cpp
cv::Mat bgr;
cv::cvtColor(rgb, bgr, cv::COLOR_RGB2BGR);
```

## 4. Gray：只保留亮度信息

灰度图每个像素只有一个数。对常见的 `CV_8UC1` 而言，`0` 是黑色，`255` 是白色。

```cpp
cv::Mat gray;
cv::cvtColor(bgr, gray, cv::COLOR_BGR2GRAY);
```

### 4.1 灰度不是简单平均

常见的 8 位 BGR 转灰度近似为：

```text
Gray ≈ 0.114 × B + 0.587 × G + 0.299 × R
```

绿色权重较高，是因为人眼对绿色附近的亮度变化更敏感。直接平均三个通道通常不等价。

从 BGR 到 Gray 会丢失颜色信息；Gray 再转回 BGR 只能把同一个亮度复制到三个通道，无法恢复原来的颜色：

```cpp
cv::Mat bgrFromGray;
cv::cvtColor(gray, bgrFromGray, cv::COLOR_GRAY2BGR);
```

## 5. HSV：把颜色和明暗拆开

HSV 的三个通道是：

- **H（Hue，色相）**：颜色类别；
- **S（Saturation，饱和度）**：颜色的纯度，越低越接近灰色；
- **V（Value，明度）**：整体明暗，越低越黑。

```cpp
cv::Mat hsv;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);
```

### 5.1 OpenCV 8 位 HSV 的实际范围

对于常见的 `CV_8UC3` HSV 图像：

| 通道  | OpenCV 8 位范围 | 含义                        |     |
| --- | -----------: | ------------------------- | --- |
| `H` |      `0~179` | 色相角度的一半（约等于 `0~360°` 的压缩） |     |
| `S` |      `0~255` | 饱和度                       |     |
| `V` |      `0~255` | 明度                        |     |

网上看到 `H=0~360` 的示例时，不能直接复制到 `cv::inRange`。红色靠近色相区间的两端（接近 `0` 和 `179`），所以红色分割经常需要两个范围。

### 5.2 HSV 颜色分割基本流程

```cpp
cv::Mat hsv, mask;
cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

const cv::Scalar lower(90, 80, 50);
const cv::Scalar upper(130, 255, 255);
cv::inRange(hsv, lower, upper, mask);

cv::Mat result;
bgr.copyTo(result, mask);
```

`mask` 是单通道 8 位图：满足范围的像素为 `255`，不满足的为 `0`。它是一张“选中/未选中”的黑白图。

#### 5.2.1 这段代码到底做了什么

可以把颜色分割理解成“逐像素筛选”：对图片中的每个像素，检查它的 `H`、`S`、`V` 是否都落在指定范围内。

整个过程可以概括为：

```text
BGR 原图
  ↓ cvtColor
HSV 图像
  ↓ 根据 H、S、V 设置上下限
mask 掩码
  ↓ 用 mask 从原图中筛选
目标颜色区域
```

以蓝色分割为例：

```cpp
const cv::Scalar lower(90, 80, 50);
const cv::Scalar upper(130, 255, 255);
```

这两个 `Scalar` 的三个数分别对应 `H`、`S`、`V`，表示：

```text
90  <= H <= 130
80  <= S <= 255
50  <= V <= 255
```

三个条件必须同时满足。`cv::inRange` 的逻辑可以近似写成：

```cpp
if (90 <= H && H <= 130 &&
    80 <= S && S <= 255 &&
    50 <= V && V <= 255) {
    mask(y, x) = 255;  // 选中这个像素
} else {
    mask(y, x) = 0;    // 排除这个像素
}
```

例如：

| HSV 像素 | 是否选中 | 原因 |
| --- | --- | --- |
| `(110, 200, 220)` | 是 | 色相接近蓝色，颜色较纯且足够明亮 |
| `(110, 200, 30)` | 否 | `V` 太低，像素太暗 |
| `(110, 30, 220)` | 否 | `S` 太低，颜色接近灰色 |
| `(60, 200, 220)` | 否 | `H` 不在蓝色范围内 |

因此，`mask` 中的白色区域表示“可能是目标颜色”，黑色区域表示“不是目标颜色”。它不是原图，而是一张选择结果图。

#### 5.2.2 `copyTo` 如何提取目标区域

```cpp
cv::Mat result;
bgr.copyTo(result, mask);
```

这里的 `mask` 相当于一张开关图：

- `mask` 为 `255` 的位置：把 `bgr` 中对应的像素复制到 `result`；
- `mask` 为 `0` 的位置：`result` 中对应位置保持黑色。

所以 `result` 就是“保留原图颜色的目标区域”。如果只想查看筛选范围本身，可以直接显示 `mask`：

```cpp
cv::imshow("Mask", mask);
cv::imshow("Result", result);
```

调试颜色分割时，最好同时观察原图、`mask` 和 `result`：先看 `mask` 是否正确选中了目标，再判断提取结果是否符合预期。

#### 5.2.3 阈值应该怎么调

通常按 `H`、`S`、`V` 的顺序调整：

1. **先调 `H`**：确定目标颜色的大致范围。目标没有完全变白时扩大范围；其他颜色也被选中时缩小范围。
2. **再调 `S`**：如果白色、灰色背景被误选中，提高 `S` 下限，要求颜色更加鲜艳。
3. **最后调 `V`**：如果阴影或过暗区域被误选中，提高 `V` 下限；但过高可能丢失目标的阴暗部分。

这些阈值不是固定的颜色常数，而是与摄像头、光照和场景有关的经验范围。实际调参时，应该一边显示 `mask`，一边修改上下限观察结果。

红色需要拆成两段再合并：

```cpp
cv::Mat red1, red2, redMask;
cv::inRange(hsv, cv::Scalar(0, 80, 50),
            cv::Scalar(10, 255, 255), red1);
cv::inRange(hsv, cv::Scalar(170, 80, 50),
            cv::Scalar(179, 255, 255), red2);
cv::bitwise_or(red1, red2, redMask);
```

HSV 不能自动解决光照问题。阴影会降低 `V`，反光可能让 `S` 变低，不同摄像头的白平衡也会改变 `H` 和 `S`。阈值必须用真实摄像头和场景测试。

## 6. Lab：更接近感知的颜色表示

Lab 常写成 `L*、a*、b*`：

- `L*`：明度；
- `a*`：从绿色到红色；
- `b*`：从蓝色到黄色。

```cpp
cv::Mat lab;
cv::cvtColor(bgr, lab, cv::COLOR_BGR2Lab);
```

对常见的 8 位 Lab 图像，`L` 大致是 `0~255`，`a`、`b` 也存为 `0~255`，中性值附近约为 `128`。浮点 Lab 的范围和含义不同，所以写阈值前要确认输入深度并打印实际范围，不能把 8 位阈值直接用于 `CV_32F` Lab。

## 7. YCrCb：亮度与色度分离

YCrCb 通常把 `Y` 看作亮度，`Cr` 看作红色差分量，`Cb` 看作蓝色差分量：

```cpp
cv::Mat ycrcb;
cv::cvtColor(bgr, ycrcb, cv::COLOR_BGR2YCrCb);
```

它常见于视频和肤色分析。和 HSV、Lab 一样，不能把 YCrCb 矩阵直接当作 BGR 显示；应先拆分通道。

## 8. 如何正确查看各通道

直接 `imshow("HSV", hsv)` 会把三个数当作 B、G、R 解释，画面可能很奇怪，这不表示转换失败。应拆分通道：

```cpp
std::vector<cv::Mat> hsvChannels;
cv::split(hsv, hsvChannels);
cv::imshow("H channel", hsvChannels[0]);
cv::imshow("S channel", hsvChannels[1]);
cv::imshow("V channel", hsvChannels[2]);
```

如果是浮点通道，可先归一化后保存：

```cpp
cv::Mat preview;
cv::normalize(hsvChannels[0], preview, 0, 255,
              cv::NORM_MINMAX, CV_8U);
cv::imwrite(R"(D:\learn\Opencv\output\h_channel.png)", preview);
```

## 9. Windows 优先的完整示例

请先创建目录 `D:\learn\Opencv\output`，并把示例图片放到 `D:\learn\Opencv\data\sample.jpg`。程序会读取 BGR 图片，转换为灰度和 HSV，提取蓝色区域并保存结果。

```cpp
#include <opencv2/opencv.hpp>
#include <iostream>

int main() {
    const std::string inputPath = R"(D:\learn\Opencv\data\sample.jpg)";
    const std::string outputDir = R"(D:\learn\Opencv\output)";

    cv::Mat bgr = cv::imread(inputPath, cv::IMREAD_COLOR);
    if (bgr.empty()) {
        std::cerr << "无法读取图片：" << inputPath << '\n';
        return 1;
    }

    cv::Mat gray, hsv, blueMask, blueOnly;
    cv::cvtColor(bgr, gray, cv::COLOR_BGR2GRAY);
    cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);

    // 这里只是演示范围，不保证适合你的图片和光照
    cv::inRange(hsv, cv::Scalar(90, 80, 50),
                cv::Scalar(130, 255, 255), blueMask);
    bgr.copyTo(blueOnly, blueMask);

    const bool ok1 = cv::imwrite(outputDir + R"(\gray.png)", gray);
    const bool ok2 = cv::imwrite(outputDir + R"(\blue_mask.png)", blueMask);
    const bool ok3 = cv::imwrite(outputDir + R"(\blue_only.png)", blueOnly);
    if (!ok1 || !ok2 || !ok3) {
        std::cerr << "结果保存失败，请确认 output 目录存在且有写入权限\n";
        return 1;
    }

    cv::imshow("BGR", bgr);
    cv::imshow("Gray", gray);
    cv::imshow("Blue mask", blueMask);
    cv::imshow("Blue only", blueOnly);
    cv::waitKey(0);
    return 0;
}
```

Windows 路径有两种常见写法：

```cpp
R"(D:\learn\Opencv\data\sample.jpg)"  // 原始字符串，推荐
"D:\\learn\\Opencv\\data\\sample.jpg" // 普通字符串，反斜杠写两次
```

## 10. 数据类型和范围：高频坑

### 10.1 `CV_8UC3` 的 `3` 是通道数

```text
CV_8UC3 = 8 位无符号 + 3 通道
```

`8U` 是每个通道的存储类型，`C3` 才是通道数。HSV 的三个通道不能和 BGR 的三个通道互换使用。

### 10.2 浮点图像要先确认范围

把图像转成 `CV_32F` 不会自动归一化：

```cpp
cv::Mat float255;
bgr.convertTo(float255, CV_32FC3);              // 仍可能是 0~255

cv::Mat float01;
bgr.convertTo(float01, CV_32FC3, 1.0 / 255.0);  // 才是 0~1
```

检查范围：

```cpp
double minValue = 0.0, maxValue = 0.0;
cv::minMaxLoc(gray, &minValue, &maxValue);
std::cout << "range = " << minValue << " ~ " << maxValue << '\n';
```

### 10.3 单通道和三通道不能混用访问类型

```cpp
uchar grayPixel = gray.at<uchar>(y, x);       // CV_8UC1
cv::Vec3b bgrPixel = bgr.at<cv::Vec3b>(y, x); // CV_8UC3
```

## 11. 排查“颜色异常”的固定顺序

1. `image.empty()`：文件路径是否正确、图片是否读入成功？
2. `channels()`：当前是 `1`、`3` 还是 `4` 通道？
3. `depth()`：是 `CV_8U`、`CV_16U` 还是浮点？
4. 当前顺序：数据是 BGR 还是 RGB？是否重复转换或漏转换？
5. 当前范围：HSV 的 `H` 是否按 `0~179` 使用？浮点数据是否真的在 `0~1`？
6. 显示方式：是否把 HSV、Lab 的通道直接当 BGR 显示了？
7. 阈值样本：是否受光照、反光、白平衡或阴影影响？

可在关键节点打印：

```cpp
std::cout << "size=" << image.cols << "x" << image.rows
          << ", channels=" << image.channels()
          << ", depth=" << image.depth() << '\n';
```

## 12. 选择建议

- 只关心轮廓、边缘或明暗：`BGR -> Gray`；
- 想从背景中找某种颜色：先试 `BGR -> HSV`；
- 需要计算颜色差异：尝试 `Lab`；
- 处理视频亮度、色度或肤色：考虑 `YCrCb`；
- 交给深度学习库：确认库要求 `BGR` 还是 `RGB`，以及输入是 `0~255`、`0~1` 还是标准化浮点数。

## 13. 动手练习

1. 把同一张 BGR 图片转换为 Gray、HSV、Lab，并分别打印 `channels()` 和 `depth()`。
2. 拆分 HSV 的 `H/S/V` 三个通道，保存为 PNG，观察它们分别反映什么。
3. 用两段 `H` 范围提取红色，再尝试只用一段范围，比较差异。
4. 把一张图片从 BGR 转 RGB 后直接 `imshow`，再转回 BGR，观察颜色为什么变化。
5. 修改蓝色分割的 `S`、`V` 下限，比较阴影和反光对掩码的影响。
